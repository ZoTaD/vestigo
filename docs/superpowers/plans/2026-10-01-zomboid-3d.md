# Project Zomboid — El sobreviviente en 3D del Planificador de personaje — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Que la pestaña Personaje (`/es/project-zomboid/personaje`, `/en/project-zomboid/planner`) muestre **al sobreviviente con la ropa de su profesión**, hombre o mujer, en 3D (girarlo, respirando en el idle del juego), con una imagen fija que va en el prerender y queda si no hay WebGL.

**Architecture:**
- **Offline, en Python (sólo biblioteca estándar + Pillow + numpy, que ya están):**
  - `xfile.py` lee los `.x` de DirectX **en texto** (todos lo son, ver el inventario) y `gltf.py` escribe `.glb` (glTF 2.0 binario), pasando de mano izquierda a mano derecha;
  - `model3d.py` resuelve **el atuendo de cada profesión** con las reglas de la pantalla de creación (`ClothingSelectionDefinitions.lua`), compone la textura del cuerpo (la piel + la ropa que es sólo textura + las máscaras), convierte las piezas con modelo (pantalones, gorras, anteojos…), pinta un **afiche** por profesión y sexo con un rasterizador chico en numpy, y escribe `games/zomboid/data/outfits.json` y `site/public/zomboid/3d/**`.
- **En el sitio:**
  - `Survivor.tsx` (en el chunk del Planificador, apto para el servidor) muestra el afiche, el botón Hombre/Mujer, la descripción de lo que lleva puesto (con links a Objetos) y el botón **"Ver en 3D"**;
  - recién al tocarlo se pide `viewer3d.ts`, que trae three.js (npm, chunk propio `three`, como Leaflet), el cuerpo, las piezas y la textura, y arma la escena;
  - sin WebGL, queda el afiche.
- Nada se convierte en el build del sitio: los `.glb`, las texturas y los afiches se generan a mano con `model3d.py` y se commitean, como las teselas del mapa.

**Tech Stack:** Python 3.14 (`unittest`, Pillow 12, numpy 2.4), React 18 + Vite 5 + TS, three.js (npm) con `GLTFLoader` y `OrbitControls`, Vitest.

### Decisión: el atuendo de una profesión

La pantalla de creación (`CharacterCreationMain:randomGenericOutfit` → `dressWithDefinitions`) viste al azar: primero `default.<Sexo>` (borrando todo), después `<profesión>.<Sexo>` (o `.Female` si la profesión no define `Male`: "most of the time there's no diff"), y después los rasgos. En cada lugar del cuerpo, si no hay `chance` o `ZombRand(100) < chance`, elige al azar uno de `items`; la profesión **pisa** el lugar del `default`. Y en los desplegables de la pantalla se puede elegir cualquiera de esas listas.

El sitio necesita **un** atuendo fijo por profesión y sexo. Regla (la fija el test de la Task 3):

1. de `default.<Sexo>`, los lugares **sin `chance`** (lo que todos llevan siempre: cinturón, remera, pantalón, medias, zapatos), con el **primer** ítem de su lista;
2. de la profesión (`<Sexo>` o, si no está, `Female`), **todos** sus lugares, tengan `chance` o no, con el primer ítem: son lo que hace reconocible la profesión (la gorra de policía, el gorro de cocinero) y la pantalla los ofrece para esa profesión; pisan el lugar del `default`;
3. sin rasgos;
4. el color de una prenda que se tiñe (`m_AllowRandomTint`) es el que muestra la pantalla de creación sin tocar el selector; la Task 1 lo lee (`CharacterCreationMain:initClothing` y el color por defecto de `ItemVisual`) y lo deja en una constante con su fuente.

Ejemplos (los fija el test): Bombero hombre = cinturón, remera de bombero azul, pantalón de bombero (modelo `Bob_Trousers`), medias cortas, zapatos negros y gorra de bomberos (modelo fijo `M_BaseballCap`). Policía hombre = anteojos (`Glasses`), gorra de policía (`M_PoliceHat`), pantalón de policía, remera de policía azul…

```python
# xfile.py
@dataclass
class XFrame:
    name: str
    matrix: list[float]          # 16 números tal cual el .x (vector fila; traslación en 12–14)
    children: list["XFrame"]
    meshes: list["XMesh"]

@dataclass
class XSkin:
    bone: str
    indices: list[int]           # vértices de la malla
    weights: list[float]
    offset: list[float]          # 16 números: la matriz inversa de reposo del hueso

@dataclass
class XMesh:
    name: str
    positions: list[tuple[float, float, float]]
    faces: list[tuple[int, ...]]             # 3 o 4 índices (los cuadriláteros se parten en la Task 2)
    normals: list[tuple[float, float, float]]
    normal_faces: list[tuple[int, ...]]      # índices de normales por cara (MeshNormals tiene los suyos)
    uvs: list[tuple[float, float]]           # uno por vértice (MeshTextureCoords)
    material_faces: list[int]
    skins: list[XSkin]

@dataclass
class XKey:
    kind: int                    # 0 rotación (w, x, y, z), 1 escala, 2 posición, 4 matriz
    times: list[int]
    values: list[tuple[float, ...]]

@dataclass
class XAnimation:
    name: str
    ticks_per_second: int
    tracks: dict[str, list[XKey]]            # por nombre de hueso

@dataclass
class XFile:
    root: list[XFrame]
    animations: list[XAnimation]

class XError(Exception): ...
def read_x(path: str) -> XFile: ...          # levanta XError("<archivo>:<línea>: …") ante algo que no entiende
def walk_frames(x: XFile): ...               # todos los Frame, en orden (padre antes que hijos)
def find_frame(x: XFile, name: str) -> XFrame | None: ...

# gltf.py
def to_rh_matrix(m: list[float]) -> list[float]: ...      # S·M·S con S = diag(1, 1, −1, 1)
def to_rh_quat(q_x: tuple[float, float, float, float]) -> tuple[float, float, float, float]: ...
    # del (w, x, y, z) conjugado del .x al (x, y, z, w) de glTF, espejado en Z
def quat_matrix(q: tuple[float, float, float, float]) -> list[float]: ...  # (x, y, z, w) → 16 números, columna mayor
def decompose(m: list[float]) -> tuple[tuple, tuple, tuple]: ...  # (T, R xyzw, S)
def compose(t: tuple, r: tuple, s: tuple) -> list[float]: ...     # la inversa de decompose
def write_glb(path: str, *, frames: list[XFrame], mesh: XMesh | None, skin_root: str | None,
              animation: XAnimation | None, speed: float = 1.0, static_bone: str | None = None) -> dict: ...
    # devuelve {"vertices": n, "triangles": n, "bytes": n, "joints": n, "channels": n}
```

Reglas del conversor:
- **Vértices:** se parten donde el mismo vértice tiene dos normales o dos UV distintas (`MeshNormals` trae sus propias caras); los cuadriláteros se parten en dos triángulos; el orden de las caras se da vuelta al espejar Z.
- **UV:** el `.x` y glTF tienen el origen arriba a la izquierda: van tal cual.
- **Piel:** hasta 4 pesos por vértice (el juego trae 3), normalizados a suma 1; `inverseBindMatrices` del `offset` de cada `SkinWeights`, en la misma mano derecha.
- **Huesos:** cada `Frame` es un nodo con TRS (`decompose`), porque glTF no anima nodos con `matrix`.
- **Animación:** se escriben sólo los canales que cambian (en el idle, la escala es siempre 1 y casi todas las posiciones son fijas); tiempo = ticks / `AnimTicksPerSecond` / `speed`, con `speed` = 0,48 × 0,8 para `Bob_Idle`. Interpolación `LINEAR`.
- **Material:** uno, `baseColorTexture` sin imagen adentro (la textura la pone el sitio por atuendo), `alphaMode` `MASK` con `alphaCutoff` 0,5 si la respuesta 1 de la Task 1 dice que las máscaras borran piel.
- **Pieza fija** (`static_bone`): una malla sin piel; el sitio la cuelga del hueso con ese nombre.
- Sin fechas, sin `generator` con versión que cambie: dos corridas dan los mismos bytes.

- **Limpieza:** al desmontar o salir de la pestaña, `dispose()` libera geometrías, materiales, texturas y `renderer.dispose()` + `forceContextLoss()`.
